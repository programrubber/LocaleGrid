01 · 프로젝트 개요

기존 방식과 LocaleGrid 적용 방식 비교

분리된 locale 파일의 작성·검토 절차를 통합 그리드 중심 흐름으로 전환.

1.1 프로젝트 개요

개발 배경

언어별로 분리된 메시지 파일: messages_ko.json, messages_en.json 또는 locales/ko/login.json, locales/en/login.json

기존 JSON 편집기는 단일 파일 중심. locale별 동일 key 비교, 누락 확인, 변경 영향 검토는 수동 작업.

개발 목적

같은 category의 JSON을 key 기준으로 통합. locale별 번역을 한 화면에서 비교·수정.

저장 전 누락·구조·문자 체계 진단. 적용 전 영향 파일과 Diff 확인.

1.2 다국어 작성 흐름 비교

업무 단계기존 작성 방식LocaleGrid 적용 방식
파일 열기ko·en·ja·vi 파일을 각각 열고 반복 전환대상 JSON 하나를 열어 같은 category의 locale 자동 연결
key 비교파일별 key 목록을 직접 대조전체 key 합집합을 한 표에 표시
번역 작성각 파일에서 동일 key 위치를 찾아 개별 수정선택 행의 locale별 값을 상세 패널에서 연속 편집
누락·오류 확인빈 값, 누락 key, 구조 오류를 육안 검토상태 배지, 셀 경고, 오류 툴팁으로 원인 확인
변경 검토수정 파일과 변경 범위를 직접 확인영향 파일, 변경 건수, 파일별 Diff 미리보기
저장·공유각 JSON 저장 후 별도 자료 작성검증 후 일괄 적용 또는 현재 화면을 XLSX로 출력

작업 규모 예시

비교 대상은 key 수 × locale 수만큼 증가. 500개 key와 4개 locale은 2,000개 번역 셀에 해당.

가정 기반 기준 시나리오 검토 셀 수 = 500 key × 4 locale = 2,000 수동 검토 = 2,000 × 5초 = 166.7분 Grid 검토 = 2,000 × 2.5초 = 83.3분 예상 절감 = 83.3분, 50.0%
예시 수치. 50%는 가정 기반 산정값이며 사용자 실측값이 아님. 보수·기준·낙관 시나리오는 5장 참조.

03 · 주요 기능

대상 인식부터 파일 적용까지의 기능 구성

주요 기능별 화면 구성과 사용 흐름.

3.1 다국어 파일 대상 지정

자동 인식

대상: 설정된 locale 루트 바로 아래의 JSON. 편집기: JSON 원본 탭과 다국어 에디터 탭.

동작 흐름

  1. locales/ko/login.json 열기
  2. 다국어 에디터 탭 선택
  3. 동일 category의 locale 열 확인
지원: {category}.json, {category}_{locale}.json
비대상: 루트 밖 JSON, suffix 불일치, JSON 이외 형식

3.2 JSON 파일 에디터

이중 에디터

화면 구성: 필터·검색, 열/행 작업, 그리드, 상세 편집, 적용·취소. 변경 보호: 탭 이동·닫기 전 확인.

변경 중 이동 시 동작

  1. 값 수정 후 탭명의 (편집중) 표시 확인
  2. JSON 탭 이동 시 미반영 변경 안내
  3. 파일 닫기 시 닫기·계속 편집 선택
  4. 취소 승인 시 원본 JSON 재로드
Grid는 비교 전용. 실제 값 편집은 하단 상세 패널에서 제공.

3.3 키 추가·수정·삭제

단건 CRUD

key 작업: dot path 추가, 이름 변경, 삭제, 삭제 취소. 기존 행은 적용 전까지 삭제 후보로 유지.

동작 흐름

  1. 추가 선택 후 key 입력
  2. 하단 상세 패널에서 locale 값 입력
  3. 편집 팝업에서 key 이름 변경
  4. 삭제 또는 삭제 취소 선택
차단: 빈 key, .a, a., a..b, 중복, leaf/object 충돌
미지원: 벌크 추가, 다중 value 편집, 템플릿 복제

3.4 검색 필터·하이라이트·검색 대상 이동

순환 탐색

검색 범위: key와 모든 locale 값. 결과 표시: 대소문자 구분 없이 일치 문자열 강조.

동작 흐름

  1. 검색어 입력
  2. 500ms 후 일치 텍스트 강조 확인
  3. 이전·다음으로 결과 순환
  4. 필요 시 검색 결과만 보기 선택
숨긴 locale 값도 검색 대상. 상태 필터는 OR 조합. 검색어는 필터 결과를 다시 제한.

3.5 예외키 관리

위치 보존

예외키: __section__ 같은 root-level 설명 entry. 원본 위치·값 보존, 적용 후 일반 번역 행에서 숨김.

동작 흐름

  1. 예외키 버튼 열기
  2. 쉼표 구분 목록 저장
  3. 새 예외키 행 추가 후 값 입력
  4. 적용 후 JSON root 위치와 값 확인
root-level 정확한 이름만 예외 처리. 중첩된 같은 이름은 일반 key. 미저장 에디터가 있으면 구조 설정 변경 차단.

3.6 드래그·버튼 이동

원본 순서 중심

이동 방식: 위·아래 버튼 또는 6-dot 핸들. 같은 top-level 안에서는 행 단위, 그룹 사이에서는 최상위 그룹 단위 이동.

동작 흐름

  1. 상태 필터와 결과만 보기 해제
  2. 같은 그룹에서 행을 위·아래로 이동
  3. 다른 그룹 경계로 드래그
  4. 적용 미리보기에서 순서 변경 확인
정렬 정책: 현재 연 파일의 원본 순서 우선. 임의 알파벳 정렬 미지원. 예외키 그룹 경계 보존.

3.7 상태 정의

배지·툴팁·스크롤맵

상태 정보: 추가·편집·삭제·경고·에러. 셀 툴팁에는 key·locale·진단 사유, 스크롤맵에는 상태 위치 표시.

상태 정의

  • 추가: 적용 시 새로 기록할 행
  • 편집: key 또는 값이 변경된 행
  • 삭제: 적용 시 제거할 기존 행
  • 경고: 확인이 필요하지만 기본 정책에서 저장 가능한 진단
  • 에러: 적용을 차단하는 진단
삭제는 단독 상태다. 그 외에는 에러 + 추가/편집 + 경고가 함께 표시될 수 있다. 스크롤맵 우선순위는 에러 → 삭제 → 추가 → 편집 → 경고다.

3.8 부적격 언어 보조 진단

예상 문자 체계 검사

검출 기준: locale별 예상 Unicode Script. 표시 정보: 위반 문자와 locale. 자연어 의미 판별은 미지원.

동작 흐름

  1. ko 값에 일본어 문자 입력
  2. 해당 셀의 경고와 툴팁 확인
  3. 설정에서 처리 수준을 ERROR로 변경
  4. 같은 위반의 적용 차단 확인
기본 정책은 WARNING. ERROR로 변경 가능. CLDR는 locale → 예상 Script 매핑에만 사용.
locale명시 허용 Script대표 진단 예
koHangul + Latin + Common + Inherited일본어 Kana, Cyrillic 등
enLatin + Common + InheritedHangul, Kana, Cyrillic 등
jaHiragana + Katakana + Han + Latin + Common + InheritedHangul, Cyrillic 등
viLatin + Common + InheritedHangul, Kana, Cyrillic 등
기타BCP 47 명시 Script 또는 CLDR likely-subtags 예상 Script + Latin/Common/Inherited결정된 Script 밖 문자
지원 범위. 제품명과 기술 용어를 위해 Latin 허용. 영어·프랑스어·베트남어 문장만 있는 ko 또는 ja 값은 통과 가능. 일본어 Han과 중국어 Han도 문자만으로 구분 불가. 잘못된 locale 또는 CLDR에서 Script를 정하지 못한 locale은 검사 제외.
현재 검출 범위. ko는 한글과 Latin을 함께 허용하므로 영어만 입력된 값은 경고 대상이 아님. 의미 기반 검출에는 자연어 판별 또는 locale별 Latin 비율 정책 필요.

3.9 누락키 검출

저장 가능 경고

누락 기준: 전체 locale의 key 합집합. 특정 locale의 key 부재, 빈 문자열, locale 파일 부재를 각각 구분.

동작 흐름

  1. 한 locale에만 없는 key 준비
  2. 통합 표에서 누락 셀 확인
  3. 해당 행 선택 후 하단 필드에 값 입력
  4. locale 파일 부재 시 적용 단계의 생성 여부 확인
구분: ① 파일은 있으나 key 없음 ② key는 있으나 빈 값 ③ locale 파일 자체 없음. 기본값은 WARNING이며 적용을 막지 않는다.

3.10 엑셀 다운로드

XLSX Export

출력 범위: 현재 화면의 행과 열. 형식: 단일 시트 XLSX. CSV와 Excel Import는 미지원.

동작 흐름

  1. 상태 필터와 표시 locale 열 선택
  2. Excel 버튼 선택
  3. 저장 건수와 열 확인
  4. 완료 후 파일 또는 폴더 열기
형식: .xlsx, 시트명 LocaleGrid, 첫 행 고정, AutoFilter, 굵은 헤더
위치: Downloads, 없으면 사용자 홈
미지원: CSV, XLSX Import
항목출력 규칙
행현재 필터로 보이는 Row만 포함
열현재 표시 열만 포함. 드래그 핸들 열 제외
폭상태 12, key 36, locale 28
문자열특수 문자를 포함한 셀 값 유지
중복 파일명숫자 suffix 추가

3.11 적용 및 취소

확인 후 저장

적용: 대기 입력 반영, 전체 재검증, 미리보기, 저장. 취소: 확인 후 원본 JSON 재로드.

팝업 유형

  1. ERROR 발생 시 차단 안내
  2. 값이 있는 누락 locale 파일의 생성 여부 확인
  3. 검증 통과 후 적용 미리보기
  4. 취소 선택 시 변경 폐기 여부 확인
  5. JSON 탭 이동·파일 닫기 전 미적용 변경 확인
파일 생성 또는 저장 취소 시 프로젝트 파일 변경 없음. 편집 상태 유지.

3.12 적용 팝업의 변경 및 현황

파일별 Diff

적용 팝업: 변경 예정 건수, 영향 파일, 파일별 변경 전·후 JSON Diff.

동작 흐름

  1. 추가·편집·삭제·경고 건수 확인
  2. 영향 파일의 생성·변경·변경 없음 상태 확인
  3. 파일별 접이식 Diff 검토
  4. 적용 승인
  5. 저장 결과와 재로드 상태 확인
저장 전 전체 파일 생성 가능 여부 확인. 구조·경로 충돌 시 저장 중단.

3.13 상세 값 편집·표시 열·확대 화면 대응

가독성 유지

상세 편집: 단일 행 기준 locale별 문자열 입력. 확대 화면: 버튼 라벨을 보존하고 표시 열 수에 맞춰 표 폭 조정.

동작 흐름

  1. 표시할 locale 열 선택
  2. 행 하나 선택
  3. 하단의 locale별 문자열 수정
  4. 300ms 후 검증과 표 갱신 확인
  5. 여러 행 선택 시 삭제·삭제 취소만 사용
string과 missing 값만 편집 가능. number, boolean, array는 readonly. 다수 열은 가로 스크롤 유지.

확대 환경의 기존 화면

버튼 라벨 잘림과 표 우측 공백 발생.

4.3 자주 묻는 질문

모든 JSON 파일에 다국어 에디터 탭이 표시되는가?
아니다. 설정된 locale 루트 바로 아래의 {locale}/{category}.json 또는 suffix가 일치하는 {category}_{locale}.json만 대상이다.
기존 메시지 파일과 충돌하면 어떻게 되는가?
중복 key, 잘못된 dot path, leaf/object 충돌은 ERROR이며 적용 불가. 원본 JSON의 중복 구조는 JSON 탭에서 선행 정리 필요.
새 언어를 추가하려면 어떻게 하는가?
locales/{새 locale}/ 디렉터리 추가. 수동 순서를 사용하는 프로젝트는 설정의 locale 목록에도 추가. 없는 category 파일은 값 입력과 생성 동의 후 생성 가능.
그리드 셀을 직접 편집할 수 있는가?
표는 비교 전용. 단일 행 선택 후 하단 상세 패널에서 locale별 문자열 편집.
number, boolean, array를 수정할 수 있는가?
문자열과 missing 값만 편집 가능. 나머지 leaf는 readonly.
숨긴 locale 값이 검색되는 이유는 무엇인가?
검색 범위는 표시 여부와 무관한 전체 locale 값. 표시 열과 검색 범위는 별개.
상태 필터를 여러 개 선택하면 어떻게 동작하는가?
선택 상태 중 하나라도 일치하면 표시되는 OR 조건. 검색어는 해당 결과를 다시 제한.
행 이동 버튼이 비활성화되는 이유는 무엇인가?
상태 필터 또는 검색 결과만 보기가 켜져 있으면 순서 변경을 막는다. 전체 순서가 보이는 상태에서만 이동할 수 있다.
CLDR가 실제 언어를 판별하는가?
CLDR의 역할은 locale과 예상 Unicode Script 연결. 같은 Script 언어와 Latin 기반 언어의 의미 구분은 불가.
한국어·영어·일본어·베트남어 외 locale도 지원하는가?
올바른 BCP 47 태그는 명시 Script 또는 CLDR likely-subtags로 예상 Script 결정. Script 결정 불가 locale은 문자 체계 검사 제외. JSON 비교·편집과 문자 검사 지원 범위는 별개.
누락 locale 파일은 자동으로 생성되는가?
해당 locale 값 입력과 적용 시 생성 동의가 모두 있는 경우에만 생성.
Excel 파일이 일부 행과 열만 포함하는 이유는 무엇인가?
내보내기 범위는 현재 필터 결과와 표시 열. 전체 원본 Export는 미지원.
CSV 또는 Excel Import를 지원하는가?
XLSX Export만 지원. 예외키 설정의 CSV는 쉼표 구분 문자열이며 CSV 파일 기능과 무관.
벌크 추가, 행 복제, 자동 번역을 지원하는가?
미지원. 단일 key 추가와 수동 값 편집만 제공.
취소한 변경을 플러그인에서 복구할 수 있는가?
플러그인 자체 backup·rollback 미지원. 프로젝트 변경 이력 또는 PyCharm Local History 이용.

목표 범위

5.3 품질 향상 산정

누락·구조·문자 체계 진단은 사후 수정 전 결함 발견을 지원. 효과 측정은 seeded defect 파일럿 기준.

D = 작업 주기당 실제 결함 수 r_manual = 수동 사전 발견률 r_grid = LocaleGrid 사전 발견률 t_rework = 미발견 결함 1건의 사후 수정 시간 예상 재작업 절감 = D × (r_grid - r_manual) × t_rework

70% 감소 목표 예

검토 대상 결함 20건, 사전 발견 14건, 사후 잔여 6건 가정.

(20 - 6) ÷ 20 = 70%

실측 전 가정.

재작업 시간 예

D=10, 수동 발견률 60%, Grid 발견률 90%, 건당 8분 가정.

10 × (0.9 - 0.6) × 8 = 24분/주기
