LocaleGrid LLM 다국어 제안 기능 설계서 (다중 모델 지원)

지원 모델: qwen3.6-27b deepseek-v3 llama-3.3 gpt-4o-mini (자유 확장) 통신 규격: 범용 OpenAI Chat Completion 호환 REST API 작성일: 2026-09-05

1. 적용 시 사용자 경험 (UX) 흐름

사내 LLM을 연동하여, 키명 옆의 버튼 클릭 한 번으로 입력된 모든 언어 문맥을 AI에게 전달하고 칩(Chip) 형태로 추천 번역을 받아 선택적으로 적용합니다.

1. 키명 옆 [✨ AI 번역 제안]

하단 패널의 Key 이름 바로 옆에 위치한 버튼을 누르면 버튼에 로딩 스피너가 돌며, 현재 행에 이미 입력된 모든 언어 문장을 Qwen 모델에 참조 문맥으로 전달합니다.

2. 칩(Chip) 형태의 추천 및 선택 적용

번역이 비어 있는 언어 입력란 상단에 ✨ 추천 번역 칩이 나타납니다. 칩을 클릭하면 해당 문구가 입력란에 즉시 반영되며 칩이 닫힙니다.

3. 자연스러운 '편집' 상태 관리

적용된 셀은 불필요한 'AI 제안' 수식어 없이 기존 편집 작업과 동일하게 '편집(노란색)' 상태로만 산뜻하게 표시되며, 검토 후 저장(적용)할 수 있습니다.

화면 적용 시뮬레이션 (UI Mockups)

실제 다국어 에디터 화면 및 IDE 설정 창에 AI 제안 기능이 통합된 고해상도 목업 화면입니다.

① 다국어 에디터 화면 (키명 옆 제안 버튼 및 칩 형태 추천 UI)

login.forgotPassword 행에서 [✨ AI 번역 제안] 버튼을 클릭하면, 이미 채워져 있는 en: "Forgot password?"를 참조 문맥으로 전달하여 비어 있는 ko와 ja 입력란 위에 보라색 추천 칩이 생성됩니다. 칩을 클릭하면 입력란에 바로 반영됩니다.

② IDE 설정 화면 (사내 Qwen 3.6-27B 엔드포인트 연동)

Settings > Tools > LocaleGrid 에서 사내 OpenAI 규격 LLM 엔드포인트 URL과 모델 식별자를 지정하고 [연결 테스트]를 수행합니다.

2. 다중 언어 문맥 전달 및 Qwen 프롬프트 설계

검토 결과: 하단 패널에 입력된 여러 언어의 문장을 모두 AI에게 전달하는 방식은 단어의 의미 다의성(Disambiguation)을 완벽히 해소하고 플레이스홀더 순서 최적화에 매우 탁월한 고품질 번역 기법입니다.

  "model": "qwen3.6-27b",
  "temperature": 0.2,
  "response_format": { "type": "json_object" },
  "messages": [

3. 아키텍처 및 내부 구현 컴포넌트

컴포넌트 역할 비고
LocaleGridSettingsState 사내 엔드포인트 URL, 모델명, API Key, 타임아웃, 기본 원본 언어 저장 IntelliJ PersistentStateComponent
LocaleGridLlmClient java.net.http.HttpClient 기반 비동기 OpenAI REST 통신 외부 의존성 없이 표준 Java 17 사용
TranslationSuggestionService 프롬프트 조립, JSON 응답 파싱, 변수 보존 검증 {0} 등 플레이스홀더 검증 로직 포함
LocaleGridFileEditor 상세 패널 '✨ AI 제안' 버튼 및 툴바 액션 UI 통합 SwingWorker / Background Task로 UI 프리징 방지

4. 안전장치 및 기대 효과

  • UI 프리징 방지: 모든 네트워크 요청은 IntelliJ ProgressManager.run(Task.Backgroundable)을 통해 백그라운드에서 실행되며 작업 취소가 가능합니다.
  • 기존 문자셋 검증 연계: 생성된 번역 결과는 LocaleGrid의 기존 LocaleScriptValidator를 거쳐 일본어(가나/한자), 베트남어(성조 라틴) 등 올바른 문자셋인지 자동 교차 점검됩니다.
  • 안전한 검토 흐름: AI 제안 즉시 파일이 저장되는 것이 아니라, 에디터의 편집(노란색) 상태로 올라가므로 개발자가 확인 후 적용(저장) 또는 취소할 수 있습니다.
